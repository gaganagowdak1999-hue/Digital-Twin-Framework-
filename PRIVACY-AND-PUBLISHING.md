# Public publishing checklist

This showcase was assembled from a supplied university project archive. Before making the repository public, confirm that university/project rules allow publication of the included architecture image and descriptive technical documentation.

## Excluded from this showcase

- Original application source code
- IFC building model files
- Sensor exports and runtime telemetry
- Environment files and credentials
- Database dumps
- Dockerfiles, Compose files, broker configuration, and deployment scripts
- University-specific runtime endpoints and hostnames

## Before publishing

- [ ] Confirm permission to publish the architecture image.
- [ ] Confirm that the project description may be shared publicly.
- [ ] Review all screenshots/images for names, building identifiers, floor plans, sensor IDs, URLs, tokens, and personal data.
- [ ] Complete `CONTRIBUTIONS.md` accurately.
- [ ] Do not add original project files merely to make the repository look more substantial.
- [ ] If permission for the architecture image is unclear, remove `images/system-architecture.jpg` and the image reference in `README.md`.

This checklist is not a legal determination of publication rights.
